1. 模型到底在计算什么？

先把“理解一句话”变成可观察的计算。生成式语言模型接收一串 token ID，输出下一 token 在词表上的概率分布；选出一个 token 后把它接在序列末尾，再重复。token 是分词器的单位，不保证一个汉字、单词或代码符号恰好对应一个 token。词表索引经过 embedding 查表成为向量，后续层不断更新这些向量。

一个简化的数据流是：ID → embedding → 多层 Transformer → 词表 logits → 采样/选取 → 新 ID。logits 不是概率，通常还需要归一化与解码规则。模型参数记录训练得到的规律；当前输入提供本次任务的条件，两者不能混为一谈。

LLM 属于 NLP，并不取代“自然语言处理”这个问题领域。旧方法也可能有上下文、生成能力和预训练。真正需要比较的是任务覆盖、训练方式、数据需求、资源开销与可控性，而不是“大模型智能，小模型不智能”这类二分法。本文用手算与自造实验解释机制，不把例子中的参数当作真实模型权重。

2. 为什么有 Q、K、V 三种投影？

设输入 X 有 T 行，每行 d_model 个数。对于一个注意力头，W_Q、W_K 的形状是 d_model×d_k，W_V 是 d_model×d_v，于是 Q、K 为 T×d_k，V 为 T×d_v。Q 的一行表示“当前位置如何查询”，K 的一行表示“这个位置怎样被匹配”，V 的一行则是被聚合的内容。

把匹配和内容分离的意义在于：模型可以学习“依据什么找”和“找到后拿走什么”这两套变换。它们并不是三个独立的文本数据库，也不应按字面理解为人工编写的问题与答案。不同层、不同头可形成不同的匹配特征。注意力原论文给出了缩放点积与多头的基本形式。

X: [T, d_model]
Q = X @ W_Q            # [T, d_k]
K = X @ W_K            # [T, d_k]
V = X @ W_V            # [T, d_v]
S = Q @ K.T / sqrt(d_k) # [T, T]
P = softmax(S + mask, axis=-1)
O = P @ V              # [T, d_v]

先检查最后两个乘法的内维度：T×T 乘 T×d_v，得到 T×d_v。P 的第 i 行描述“第 i 个位置读取所有可见位置的比例”，而不是第 i 个词在整篇文章中的重要程度。

3. 手算一个只有两个位置的注意力

为了让中间结果可复算，直接给出投影后的向量，取 d_k=d_v=2。Q 与 K 都是 [[1,0],[0,1]]，V=[[10,0],[0,20]]。这不是自然语言模型，只是一次矩阵运算的教学输入。

点积矩阵为 [[1,0],[0,1]]，除以 √2 后，对角线为 0.7071。若没有因果掩码，第一行 Softmax 为 [0.6698,0.3302]，第二行为 [0.3302,0.6698]；输出约为 [6.6976,6.6048] 与 [3.3024,13.3952]。这说明输出是 V 的加权组合，而不是“选最大分数对应的值”。

换成因果掩码，位置 0 不允许读位置 1，所以第一行分数变成 [0.7071,−∞]，权重变为 [1,0]，输出正好 [10,0]。位置 1 可以读前两个位置，结果仍为 [3.3024,13.3952]。掩码加在 Softmax 之前；若归一化后简单清零未来权重，却不重新归一化，会改变输出尺度。

缩放的直观理由可以从方差看：若各维独立且单位方差，d_k 项乘积之和的方差随 d_k 增长；除以 √d_k 使量级更稳定。这是帮助理解的理想化分析，不表示训练中的真实向量总满足独立性假设。

4. 用不到二十行逻辑复现，先验证再优化

下面程序只使用 Python 标准库，目的是暴露计算顺序，不追求性能。它返回权重和输出，便于检查每一个中间量。先用双精度得到参考值，再考虑浮点误差、并行归约和硬件实现。

import math

def attention(Q, K, V, causal):
    weights, output = [], []
    scale = math.sqrt(len(Q[0]))
    for i, q in enumerate(Q):
        scores = [sum(a*b for a,b in zip(q,k))/scale for k in K]
        if causal:
            scores = [s if j <= i else -math.inf for j,s in enumerate(scores)]
        m = max(scores)
        exps = [math.exp(s-m) for s in scores]
        probs = [x/sum(exps) for x in exps]
        weights.append(probs)
        output.append([sum(probs[j]*V[j][c] for j in range(len(V)))
                       for c in range(len(V[0]))])
    return weights, output

Q = K = [[1., 0.], [0., 1.]]
V = [[10., 0.], [0., 20.]]
print(attention(Q, K, V, True))

减去每行最大值 m 不改变 Softmax 的结果，却避免指数溢出。此例保证每行至少有一个可见位置；生产代码必须明确“整行被屏蔽”时的行为，否则可能出现 −∞−(−∞) 和 NaN。三项基础断言是：权重和约为 1、未来权重为 0、输出形状正确。

5. 注意力不是整个 Transformer

注意力主要进行跨位置的信息交换。逐位置前馈网络则对每个位置的表示做非线性变换；残差路径允许新变换与已有表示结合，归一化帮助控制数值与优化行为。具体模型可能采用不同的归一化位置、激活函数和前馈结构，不能把某一版示意图当作所有 LLM 的固定实现。

多头不是把同一结果算几遍再平均。不同投影允许各头在不同子空间工作，输出拼接后经投影回到模型维度。若 d_model=8、头数=2、每头输出宽度=4，两个 T×4 输出拼为 T×8。真实实现常把这些线性变换合并成大矩阵乘，数学上的“多个头”不意味着要启动同样多的独立程序。

学习一个具体架构时，建议按“张量形状、权重布局、归一化位置、KV 头数、位置编码”逐项读配置，再对照实现。Llama 3 技术报告可用于具体案例。至于“自己的项目为什么选 Llama 3”，还需要实际硬件、许可证、语种、效果与部署证据，不能由架构介绍替代个人决策。

6. 顺序信息如何进入计算？

如果只把一批内容向量输入普通自注意力，置换输入会相应置换输出，计算本身没有额外的“第几个位置”坐标。因此需要位置机制。绝对位置向量可以与词向量相加，相对位置偏置可以影响分数，RoPE 则在 Q、K 上进行与位置有关的旋转。

对一个二维分量，旋转矩阵 R(θ) 保持向量长度。位置 m、n 分别用 R(mθ)、R(nθ)，二者点积满足 (R(mθ)q)ᵀ(R(nθ)k)=qᵀR((n−m)θ)k。关键不是“把位置编号塞进向量”，而是匹配结果显式依赖位置差。更高维会把分量配对并使用不同频率。RoFormer 原论文描述了这种设计。

能够把公式算到更大位置，不代表模型就能可靠利用更长上下文。训练长度、位置频率、任务难度与证据分布都会影响效果。长任务中应分别测试：早期约束是否被忽略、相似实体是否混淆、最新状态是否覆盖旧状态；这些失败不能仅用“窗口还没满”排除。

7. Prefill、Decode 与 KV Cache：缓存究竟省了什么？

Prefill 一次处理已有输入前缀，生成各层的 K、V；decode 每轮只追加新位置。因果模型中的旧位置不依赖未来 token，因此在相同前缀、权重和配置下，它们的 K、V 可复用。新 Q 仍需与可见历史 K 交互，再聚合 V。KV Cache 文档解释了这种追加过程。

对一个常规稠密模型，缓存字节数近似为 2×B×L×T×H_kv×d_head×s。B 是批大小，L 是层数，T 是已缓存长度，H_kv 为 KV 头数，s 为每元素字节数；2 对应 K 和 V。以 B=1、L=32、T=4096、H_kv=8、d_head=128、s=2 为例，结果是 536870912 字节，即 512 MiB。批大小变为 4，其他不变，缓存约 2 GiB。

这个估算没有包含权重、激活、分配器碎片、页表和临时工作区，也不覆盖滑动窗口、量化缓存或分片等变化。缓存减少重复计算，但历史长度增加仍会增加读取量。区分首 token 延迟与逐 token 延迟，才能判断瓶颈是输入处理、权重读取、KV 读取还是调度。

8. GQA 为什么主要减少 KV 开销？

设 Query 头数为 32。MHA 可以有 32 组 K、V；GQA 可以只有 8 组，每 4 个 Q 头共享一组；MQA 则所有 Q 头共享一组。注意 Q 头并未因此全部合并。保持其他尺寸不变，前例若从 8 个 KV 头改为 32 个，缓存由 512 MiB 变成 2 GiB。

共享减少的是 K、V 的表示与读取，并不保证模型总体计算和延迟都同比下降。过强共享也可能影响质量。GQA 原论文研究了这种中间设计及从已有检查点适配的方式；不能把一个 MHA 模型仅通过改配置就视为等价的 GQA 模型。学习时应把“格式尺寸正确”和“语义能力保持”分成两个验收项。

9. 推测解码：用便宜的提议减少昂贵的串行步

把逐词生成想成一连串有依赖的决策。草稿模型先提出多个 token，目标模型对这一段进行验证，若接受多个，就能摊薄目标模型的调用成本。严格的推测采样不是随意接受相似答案，而是配合接受概率与拒绝后的重采样，使输出保持目标分布。推测解码原论文给出了算法依据。

用一个仅用于性能直觉的简化模型：一轮草稿耗时 D、目标验证耗时 V，平均接受 a 个 token，并额外得到一个目标 token，那么每轮产出约 a+1 个 token，每 token 时间约 (D+V)/(a+1)。这不是完整服务性能公式，但能说明为什么接受率低或草稿太贵时可能变慢。实际还需统计 batch、调度、显存与请求长度分布，不能照搬论文里的加速倍数。

10. 把缓存解码走一遍，理解到底省了什么

把输入暂时设成三个 token：A、B、C。一次完整前向会为三个位置计算各层表示；最后一个位置的 logits 用来预测第四个 token。若采样得到 D，下一步不是把模型参数改成记住 D，而是把 D 的表示送入每层，并读取之前保存的 K 和 V。缓存属于这次请求的运行状态，模型权重属于多个请求共享的参数，二者不能混淆。

只看一个注意力头：prefill 后 K_cache、V_cache 的形状都是 [3,d]。处理 D 时，新 Q、K、V 都是 [1,d]；把新 K、V 追加后变成 [4,d]，Q 与 K_cache 的转置相乘得到 [1,4]，softmax 仍沿键位置维进行，乘 V_cache 后输出 [1,d]。随后处理 E 时长度变成5。每层有自己的缓存，不能把某一层的 K、V 拿去供另一层使用。

为什么旧位置可以不重新计算？对因果注意力，旧位置只能访问它及之前的位置，新追加的 D 不会改变 A、B、C 的可见前缀。因此在权重、位置编号及前缀不变的条件下，旧 K、V 可以复用。若修改前文 B，就不应盲目复用 B 之后的缓存，因为后续表示可能已经依赖旧 B。前缀缓存服务必须比较实际前缀及相关运行配置，而不只是比较字符串长度。

无缓存的朴素解码会反复处理整个前缀，每一步单层注意力部分约随 T² 增长；缓存后新 token 对历史的注意力约随 T 增长。但这不是“生成总成本变成常数”：生成 N 个 token 要面对逐步增长的历史，缓存还会占内存并带来读带宽压力。模型权重读取、MLP、通信和调度也都消耗时间，因此不能只用一个注意力公式预测真实吞吐。

旧缓存: K=[3,d], V=[3,d]
新输入: x_D=[1,d_model]
新投影: q_D,k_D,v_D=[1,d]
拼接后: K=[4,d], V=[4,d]
分数:   q_D @ K.T = [1,4]
权重:   softmax(scores / sqrt(d)) = [1,4]
输出:   weights @ V = [1,d]

实验时固定模型、输入和数值精度，比较“完整重算最后一个位置的 logits”与“缓存增量计算的 logits”。在浮点误差容许范围内应接近；不要要求并行内核下每个 bit 完全相同。若差异很大，先查位置编号、mask、缓存拼接顺序和 padding，再怀疑模型本身。

11. 为什么训练能并行，生成却通常逐步进行？

假设训练样本的 token 序列是 A、B、C、D。模型输入 A、B、C，监督目标对齐为 B、C、D。三处预测可以放在一个张量中同时算，但必须给注意力矩阵加因果遮罩，使预测 B 的位置看不到 B 本身及之后的内容。并行计算不等于允许查看未来。

这也解释了一个常见泄漏：若忘记遮罩，或者让标签与输入错位，训练损失可能异常漂亮，实际生成却很差，因为训练时模型在使用上线不可获得的信息。应先用极小序列画出允许访问的三角矩阵，再逐位置检查目标。

生成时没有真实的后续 token 可供一次性放入输入，通常需要先得到下一 token，再继续下一步。训练中上一位置来自真实样本，生成中来自模型自身选择，早期错误可能改变后续分布。降低温度只改变采样的分散程度，不会修复参数知识错误，也不保证正确性。

从学习顺序上，先把一个头、一个层和一个因果序列算清楚，再理解多头、多层和批处理。只背“Q 是查询，K 是键，V 是值”无法解释缓存为什么成立；能说明未来不会改变过去的表示，才真正连接了训练目标、因果遮罩与推理优化。

12. 一组能验证理解的练习

  • 把手算例子的 V 改成全相同向量 [3,7]。预期：只要每行权重和为 1，每个位置输出都等于 [3,7]。若不是，检查归一化或矩阵乘。
  • 给无掩码分数矩阵每行同时加 1000。使用减最大值的实现应保持输出；直接 exp 可能溢出。说明数值稳定与数学等价的区别。
  • 将前例因果掩码方向写反。第一个位置会读到未来，测试应该立即失败；不要只检查最终输出“看起来正常”。
  • 把 KV 缓存估算里的 T 和 B 分别翻倍，结果各翻倍。然后对真实模型实测峰值显存，解释估算与实测差额，而不是把差额都算成 KV。
  • 比较同一模型不同输入长度的首 token 和逐 token 延迟。报告模型配置、硬件、batch、输出长度、预热与重复次数；不预设哪条曲线一定线性。

达到这一章的学习目标，不是能背出 QKV 三个字母，而是能对照一个模型的计算图解释每个维度、预测掩码错误的症状、估算缓存，并设计能推翻自己判断的实验。

再做一组性能测量：保持输出长度相同，分别增加输入长度与并发请求数，记录首 token 延迟、后续 token 间隔以及峰值显存。预期输入变长首先增加需要处理的前缀工作与缓存容量；并发增大通常增加总缓存占用，但单请求延迟是否变好取决于批处理、带宽和排队，不能预先断言。

把理论值与实测显存相减，剩余部分可能包含权重、临时激活、分配器预留和框架开销。用这样的差异分析，才能判断瓶颈属于缓存、算力还是服务调度，而不是看到显存占用就把所有字节都算给 KV。
