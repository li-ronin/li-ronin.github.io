1. 先把“学什么”与“怎么省资源”分开

训练方法回答“什么信号推动参数变化”，适配方法回答“允许哪些参数变化”，数值格式回答“怎样存储和计算这些参数”。SFT、DPO、GRPO 属于第一类；LoRA 主要属于第二类；低比特量化主要属于第三类。可以用 LoRA 做 SFT，也可以对量化基座训练适配器，但它们不是同一件事。

本文贯穿一个自造任务：输入报错和环境信息，输出诊断结论以及下一步只读检查。设输入 x 为“服务端口被占用，应怎样排查？”。不同训练阶段可以使用相同主题，却需要不同标签：SFT 给合格示范，DPO 给偏好对，GRPO 给可计算反馈。例子用于理解数据结构，不是某个真实训练项目或推荐直接操作系统的指令。

预训练让模型从大量文本中学习分布规律，后训练常用于改善指令遵循、风格或任务表现。后训练并非万能补丁：若基座缺少所需能力、数据含错误或评测泄漏，换一个优化算法不会自动解决。先定义“合格输出”及可核验的标准，再决定采用哪种反馈。

2. SFT：把一条正确示范拆成逐 token 的学习信号

对示范输出 y=(y₁,…,yₙ)，自回归模型把整段概率分解为各 token 的条件概率乘积。取负对数后得到求和：L=−Σₜ log πθ(yₜ|x,y<ₜ)。这里 πθ 是当前模型，条件中的旧 token 来自正确示范，这种训练方式通常称为 teacher forcing。

若一个教学输出只有两个目标 token，模型给它们的条件概率分别为 0.8 和 0.5，那么序列概率为 0.4，总负对数似然为 −ln(0.4)=0.9163；按两个 token 平均为 0.4581。训练日志究竟使用总和还是均值会影响数字尺度，不能跨配置直接比较 loss。

在对话微调中，应明确哪些 token 参与损失：全序列、仅 completion，或仅 assistant 消息。SFT Trainer 文档说明了数据形式与损失掩码选项。模板、角色分隔符和停止标记同样是训练协议的一部分；训练时和推理时模板不一致，可能让模型把角色标记当正文。

给定训练样本：
x = "报错：端口被占用。目标：安全定位占用进程。"
y = "先查看监听进程与服务状态；确认身份后再决定如何处理。"

输入序列 = prompt_tokens + answer_tokens
标签序列 = IGNORE(prompt部分) + answer_tokens
logits[t] 用于预测下一个位置的 token
loss = 仅对有效标签位置计算的交叉熵

常见 off-by-one 错误是让位置 t 的 logits 去预测它已经看见的 token t，而非目标的下一位置。训练框架可能内部处理移位；不能外部移位一次、内部再移位一次。用三四个 token 的样本打印输入、标签和参与 loss 的位置，比直接观察大规模训练曲线更有效。

3. 好的示范不是“越长越专业”

对上面的诊断任务，示范必须覆盖未知条件、证据不足和安全边界，而不只是给出流畅答案。若所有样本都让模型立刻终止进程，模型可能学到“果断操作”比“核实归属”更常见。数据中的行为偏差会被训练目标忠实强化。

构造一组最小对照：同一错误文本，分别配上开发服务、数据库服务、无法识别的占用进程。要求输出的行动边界不同。再加入看似相近却不该共用结论的例子，例如“端口被占用”与“地址无权限绑定”。这样的对照能检验模型学的是条件关系还是关键词模板。

“需要多少条数据”没有脱离任务的标准答案。把质量固定后逐步增加样本规模，画训练与验证效果曲线；同时做重复率、来源比例和错误标签抽检。个人项目实际用了多少数据，应记录过滤前后数量、token 数、时间范围与划分依据，不能拿示例规模冒充自己的实验。

4. DPO：比较两个回答，不是简单多做一遍 SFT

标准偏好数据为 (x,y_w,y_l)，其中 w 是更受偏好的回答，l 是较差回答。例如 y_w 先核实进程身份，y_l 无条件执行破坏性操作。偏好必须有清楚准则，而不是仅按长度选较长的回答。DPO 同时比较当前策略与固定参考策略对两段回答的相对概率。

定义 Δ=log πθ(y_w|x)−log πref(y_w|x)−log πθ(y_l|x)+log πref(y_l|x)，标准 DPO 损失为 −log σ(βΔ)。πref 为参考模型，β 为目标中的系数。DPO 原论文给出了这一形式及其与 KL 约束偏好优化的联系。不要把 β 简化成在所有实现中都线性控制某一个可观察效果的旋钮。

自造数值例：当前模型对好、坏回答的序列 log probability 为 −5、−6，参考模型为 −6、−6，则 Δ=1。取 β=0.1，损失约为 −ln σ(0.1)=0.6444。若当前模型与参考模型相同，Δ=0，损失为 ln2≈0.6931。这里比较的是相对变化，不是要求好回答的绝对概率一定大于坏回答。

import math

def dpo_loss(logp_win, logp_lose, ref_win, ref_lose, beta):
    delta = (logp_win-ref_win) - (logp_lose-ref_lose)
    z = -beta * delta
    # softplus(z)，避免很大正数时 exp 溢出
    return max(z, 0.) + math.log1p(math.exp(-abs(z)))

assert abs(dpo_loss(-5, -6, -6, -6, .1)-.6443966601) < 1e-9

该函数仅验证标量损失，不是完整训练器。实际要计算回答 token 的 log probability、正确掩码并反向传播。DPO 能利用静态偏好对训练；偏好对仍可能来自之前的采样过程，这与“优化时每步必须在线采样”是两个问题。

5. GRPO：同题多次尝试，利用组内反馈更新策略

原始 GRPO 对同一个输入采样一组回答，用组内奖励估计相对优势，避免另训练一个价值模型。一个简化的优势写法是 Aᵢ=(rᵢ−mean(r))/(std(r)+ε)。完整目标还涉及新旧策略概率比、裁剪和 KL 等项；仅把奖励标准化后做交叉熵，并不是完整 GRPO。原始定义应对照DeepSeekMath，后续库和论文可能修改归一化或损失。

用人口标准差演示奖励 [1,1,0,0]：均值 0.5，标准差 0.5，于是优势为 [1,1,−1,−1]。组内相对好的回答得到正信号，差的得到负信号。若奖励全为 [1,1,1,1]，减均值后全部为 0；这组没有提供区分优劣的任务奖励信号，但完整优化中的其他约束项不一定为零。

奖励设计比公式更容易成为瓶颈。诊断任务不能简单奖励“回答包含某命令”，否则模型可以堆砌命令而不诊断。应拆成可验证的行为，例如格式合规、是否先获取证据、是否越权，以及真正的任务成功；若使用模型评分，还要单独验证评分器的误判和可被利用的漏洞。

6. 三种反馈如何对应不同问题

  • 只有可靠示范：先用 SFT 教清楚输出结构与基本行为。检查模型是否真正依赖输入条件，而不是记住固定表述。
  • 能稳定比较两个回答：偏好优化适合表达“哪个更符合要求”；偏好标签不需要等于精确的数值奖励，但不一致的偏好会产生噪声。
  • 能针对新尝试给出可靠反馈：在线策略优化有机会探索新的输出；同时付出采样、评分和稳定性控制的成本。
  • 不能可靠判断输出对错：先修评测与反馈，不要把错误评分大规模放大。

这不是从初级到高级的必经阶梯。某任务可能只需要 SFT，某任务的主要收益来自数据治理，也可能用多种阶段组合。对比实验应固定数据与资源约束，至少保留基座、SFT、加偏好优化三组；如果改算法时同时增加更高质量数据，不能把全部增益归给算法。

7. LoRA：低秩约束究竟约束了什么

对线性层 y=Wx，LoRA 将有效权重写成 W+BA，冻结原 W，仅训练 A、B。若 W 是 m×n，取 B 为 m×r、A 为 r×n，则 BA 仍为 m×n；可训练参数数目从 mn 变为 r(m+n)。这里低秩约束作用于权重增量，不意味着 W 本身低秩。LoRA 原论文给出了这种适配方式。

例如 m=n=4096，r=8：全矩阵有 16777216 个参数，而两块适配矩阵共 65536 个，为前者的 1/256。这个比例只针对该矩阵的可训练增量，不是整个训练显存或耗时缩小 256 倍。基座前向、梯度传播所需激活和其他模块仍有开销。

秩、目标层和数据质量决定适配空间。仅在注意力投影上加适配器，与同时适配前馈层，表达能力和成本不同。应同时评估目标任务增益、通用能力退化、峰值显存和吞吐。权重可合并不代表所有部署形式都没有额外开销，也不代表所有任务都适合相同秩。

8. 量化：从一个数值误差理解部署取舍

用最简单的对称均匀量化理解：给定步长 s，把实数 x 映射为整数 q=clip(round(x/s),q_min,q_max)，重建值为 x_hat=sq。没有截断且采用最近舍入时，绝对误差通常不超过 s/2；一旦超出可表示范围，截断误差可能远大于这个界。真实格式还可能有零点、分组尺度或浮点编码。

自造例子 s=0.1，x=0.26 重建为 0.3，误差 0.04；若整数上界为 7，x=1.2 会被截到 0.7，误差达 0.5。为了容纳极端值而增大步长，又会降低大量普通值的分辨率。这就是为什么校准分布、异常值与分组策略重要。

权重量化、激活量化、KV Cache 量化影响的瓶颈不同。量化文档列出了不同实现；格式支持必须与实际硬件内核一起判断。文件更小不必然更快，反量化、非对齐形状和小 batch 都可能改变收益。LoRA 与量化可以组合，但不能把“可训练参数少”当成“数值误差小”的证据。

9. 一个最小但可信的训练实验计划

首先固定任务：输入十种服务故障描述，要求生成结构化、只读诊断步骤。建立训练、验证、测试三份数据，按故障来源或模板族划分，避免同模板换个端口号就同时出现在训练与测试。保留一组完全不同表达的对照集。

每次实验记录基座版本、分词器、模板、可训练参数、样本数量与 token 数、有效 batch、学习率、训练步数、随机种子、硬件和峰值显存。将“能运行”和“有效”分开：训练 loss 下降只能说明拟合训练目标更好，还需检查实际生成。

评测至少包含：格式成功率、证据顺序正确率、越权建议率、任务成功率，以及长度和延迟。测试集冻结，调参只看验证集；对失败样本按原因分组，而不只报告一个平均分。更强的模型评分不能替代对关键行为的可核验检查。

  • SFT 数值验算：把两个正确 token 的概率都改为 0.5，总损失应为 1.3863。
  • DPO 反向对照：将好坏回答交换，前例损失应从 0.6444 变为 0.7444。解释为什么标签方向重要。
  • GRPO 信号检查：组内奖励全相同，任务优势应全零；若实现仍给出较大差异，检查标准差定义和掩码。
  • LoRA 参数检查：把 r 从 8 改成 16，适配参数翻倍；不要据此宣称整体训练显存精确翻倍。
  • 量化漂移检查：用不含异常值的数据校准，再用含异常值的数据测试，观察截断率与任务表现，不预设二者必然等比例变化。

10. 从组内优势到受约束更新：再算一步 GRPO

只看一个位置的策略更新，令旧策略在该采样 token 上的概率为0.20，新策略为0.26，则概率比 r=0.26/0.20=1.30。这里“旧策略”是生成这批训练样本时的策略；它与用来约束偏移的参考策略不是同一个概念。混淆两者会把采样修正和参考约束写成一件事。

用教学参数 ε=0.2、正优势 A=1，PPO式裁剪代理项为 min(rA, clip(r,1−ε,1+ε)A)。此时得到 min(1.30,1.20)=1.20，不会继续因为把同一正样本的概率比从1.30推到1.50而增加该项。若 A=−1 且 r=0.70，得到 min(−0.70,−0.80)=−0.80，阻止通过过度降低负样本概率无限获益。这个裁剪是代理目标的局部形状，不是保证模型分布绝不变化的硬安全边界。

实际序列包含多个位置，需要明确优势如何分配给 token、长度如何归一化、无效位置怎样 mask、KL 项如何估计。原始 GRPO 以组内相对奖励估计优势并加入参考约束；后续实现会改变标准差归一化、长度聚合或约束方式。报告实验时应写出所用实现的完整目标和版本，不能只写“用了 GRPO”就认为实验可复现。

一个检查练习：把四条奖励都设为1。采用本章组内标准化时，优势为0，因此奖励驱动的代理项不产生区分方向；这不意味着所有训练项都为0，若还保留 KL 正则，它仍可能推动策略靠近参考模型。这个边界案例能检查你是否真的把奖励信号与总损失分开理解。

11. 学会说明证据边界

公开论文告诉我们方法的目标与构造，不能自动证明某个个人项目有效。记录“为什么选择该架构”“数据为何足够”“收益来自哪里”，应该使用自己的对照实验，而不是摘录别人的最佳结果。对于商业或未公开模型，无法确认的训练细节应保留未知。

完成本文后，应能拿出三种不同的数据样本，写出各自的训练信号，解释它们如何推动参数变化，并指出实验中可能出现的反馈失真。能做到这些，再阅读训练框架的配置项就不会只是在记参数名。

微调前还应保留一个不训练的基线：同一基础模型仅通过任务说明与少量示例完成任务。若训练后只在训练模板上提高、改写措辞后下降，可能学到的是格式捷径而不是任务能力。至少测原始表达、同义改写、缺少必要条件和分布外输入，分别观察正确率与是否承认信息不足。

记录训练消耗时区分原始样本条数、去重后的样本数、参与损失的 token 数和实际优化步数。两个数据集即使都叫一万条，平均长度相差十倍、重复率不同，提供的监督信号和训练成本也可能完全不同；样本数量不是质量或能力的替代指标。
